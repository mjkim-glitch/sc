# 강의 정리 자료 세트 만들기

강의자료와 녹음(받아쓰기)만으로 시험 대비 자료 세트를 만든다. 사용자는 이 자료로 시험을 준비하므로, **자료에 없는 내용을 하나라도 지어내면 그대로 틀린 답이 된다.** 그래서 정확성이 가독성보다 먼저다. 그다음으로 사용자가 중요하게 여기는 것은 **빠짐없음**(자료·필기·녹음의 모든 내용이 어딘가에 들어감)과 **보기 편함**(수식이 깨지지 않고, 색이 보이고, 마인드맵만 봐도 뜻이 통함)이다.

과목 폴더에 CLAUDE.md가 있으면 먼저 읽는다. 그 과목만의 정보(시험 형식·배점, 받아쓰기 용어 힌트, 예전 파일 이름, 이미 정한 처리 방식, 아티팩트 주소)가 있으면 이 skill보다 그것을 따른다. 작업 중 정한 과목별 결정(범위 단서, 전사문 출처, 사용자 지시)은 그 CLAUDE.md에 한 줄씩 적어 다음 세션이 이어받게 한다.

## 절대 원칙

- 강의자료 원문, 강의자료 위 손필기, 판서 사진, 녹음 받아쓰기에 있는 내용만 사용한다. 배경지식, 보충 설명, 예시, 정의, 해석을 추가하지 않는다. (모의고사의 새 계산 문제처럼 원리를 적용해 만든 것은 그렇다고 표시한다.)
- 요약·재배열·축약·번역만 허용한다. 슬라이드 간 내용을 추론으로 연결하지 않는다.
- 출처는 대분류 첫 줄에 파일명만 적는다. 항목마다 슬라이드 번호를 붙이지 않는다.
- 잘리거나 불명확한 내용은 추측하지 말고 [원문 확인] 표시를 한다.
- 이미 만든 결과물에 내용을 추가할 때는 강의자료에서 온 기존 문장을 고치거나 지우지 않는다. 새 내용은 맞는 위치에 [강의]·[풀이] 표시와 함께 덧붙이기만 한다. 기존 문장을 바꾸는 것은 사용자가 따로 지시할 때만 한다. (사용자는 원문이 바뀌는 것을 가장 걱정한다.)
- 영어 강의자료는 한국어로 번역해 정리하고, 용어는 번역어 뒤 괄호에 영어 명칭을 함께 적는다. 예: 수요곡선(Demand Curve). 시험은 영어 용어로도 나오기 때문이다.
- 결과물을 고칠 때 원래 파일은 지우지 않고, 크게 바꾸는 것(특히 마인드맵)은 새 버전(v2, v3…)으로 만든다.

## 입력 자료 (과목 폴더 기준)

| 자료 | 위치(예) | 필수 |
| --- | --- | --- |
| 강의자료(PDF·PPT) — 손필기가 PDF에 합쳐져 있을 수 있음 | 강의자료/ | 필수 |
| 녹음 파일 / 이미 있는 전사문(클로바노트 등) | 녹음/ (전사문/), transcripts/ | 강의 후 작업에서 필수 |
| 판서 사진 | 판서/ | 있으면 |
| 시험 형식·범위 | 사용자에게 받거나 녹음·필기의 공지에서 찾음 | 모의고사에 필요 |

- 주차와 챕터가 일치하지 않을 수 있다. 녹음은 파일 이름이 아니라 **받아쓰기 내용**으로 어느 챕터·슬라이드인지 정한다.
- 시험 범위 단서(예: 필기 "중간고사 ~시험범위 ←", 녹음 "여기까지가 중간고사 범위")를 찾으면 둘을 맞춰 보고 범위를 정한다. 범위 밖 내용도 노트에는 넣되 (시험범위 밖)으로 표시한다.

## 1단계: 작업 시작 질문

먼저 AskUserQuestion으로 범위를 묻는다. 대화나 파일에서 이미 답이 분명하면 묻지 않는다.

- 질문 1. 정리 기준: 1) 단일 강의 기준 2) 시험 범위 전체 기준
- 질문 2. 1)이면 몇 강인지·예습/복습인지, 2)이면 어느 시험인지·범위
- 시험 형식을 모르면 OX·단답형·계산·그래프·서술형을 체크 선택지(multiSelect)로 묻는다. "계산이 많다", "기간별(1기·2기·3기) 계산" 같은 정보가 있으면 모의고사 비중에 그대로 반영한다.
- 그래프가 많은 과목이면 그래프를 어떻게 보존할지(그림으로 넣고 글로도 옮기기)를 확인한다.
- 각 단계의 예상 소요 시간을 대강 알려 준다. 오래 걸리는 작업은 사용자 응답 없이 계속 진행하되, 짧은 진행 상황과 끝날 예상 시각을 중간중간 알린다.

## 2단계: 결과물과 파일 이름

파일 이름은 `{강의명}_{범위}_{결과물}` 형식이다. {범위}는 `n강` 또는 `n강~m강`(주차 단위면 n주차 = n강).

| 순서 | 결과물 | 파일 | 강의 전 | 강의 후 | 시험 범위 전체 |
| --- | --- | --- | --- | --- | --- |
| 0 | 마인드맵(개념 구조도) | {…}_마인드맵.md (+ 웹 페이지, 프린트용 PDF) | O | O | O |
| 1 | 스터디 가이드 | {…}_스터디가이드.md + .docx | O (예습용) | O | O |
| 2 | 정리 노트 | {…}_study note.md + .docx | O (강의자료만) | O | O |
| 3 | 모의고사 | {…}_모의고사.md + .docx | O (자가 점검용) | O | O |
| 4 | 웹 페이지 묶음(아티팩트) | web/ → 아티팩트 1개 | 요청 시 | 요청 시·제안 | 요청 시·제안 |

- 마인드맵·가이드·모의고사는 노트의 절 번호를 가리키므로 **노트 목차(절 번호)를 먼저 확정한다.**
- 결과물 하나가 끝날 때마다 사용자에게 알린다.
- .md 미리보기에서는 색·형광펜이 보이지 않는다. 색 표시가 있는 결과물(노트·가이드·모의고사)은 Word 사본이나 웹 페이지로 보이게 한다. 사용자가 "색이 안 보인다"고 하기 전에 먼저 만들어 둔다.
- 폴더에 다른 이름으로 이미 만든 파일이 있으면 지우거나 이름을 바꾸지 않는다.

### 모드별 차이

- **강의 전(예습)**: 강의자료만 쓴다. [강의] 표시는 없다. 가이드의 "교수 강조" 칸 대신 "강의에서 확인할 것"을 둔다. 모의고사 첫 줄에 "강의 전 버전". 녹음이 생기면 같은 파일에 덧붙여 강의 후 기준으로 갱신한다.
- **강의 후(복습)**: 강의자료·필기·판서·녹음을 함께 쓴다.
- **시험 범위 전체**: 범위 안의 강의별 study note가 있으면 모아 쓰고, 없으면 원자료에서 만든다.

- claude.ai에서는 한 번에 처리할 수 있는 분량이 작다. 범위가 크면 장(챕터) 단위로 나눠 하나씩 끝내고, 끝날 때마다 파일을 넘긴다.
- 모바일 사용자는 화면이 작다. 진행 보고는 짧게, 결과는 웹 페이지(HTML)·PDF·Word 파일로 넘긴다.
- 스크립트는 `python -I <skill>/scripts/…` 처럼 부른다(`-I`는 내려받은 자료를 다루기 때문). 한글 출력이 깨지면 `PYTHONIOENCODING=utf-8`.

## 3단계: 자료 준비

자세한 설치·스크립트 목록은 `scripts/setup.md`.

1. 강의자료 추출: `python -I scripts/extract_pdf.py 강의자료/*.pdf --outdir extracted` — 쪽별 텍스트와 쪽 이미지. 손필기·그래프·잘린 글자는 쪽 이미지를 확대해서 직접 본다(손필기는 주석 객체가 아니라 그림으로 합쳐져 있는 경우가 많아 텍스트 추출에 안 나온다).
2. 녹음: `references/transcription.md`를 읽는다. **이미 있는 전사문(클로바노트 등)이 있는지 먼저 확인**하고, 길이가 녹음과 맞으면 그것을 쓴다. 받아쓰기는 오래 걸리므로 백그라운드로 돌리고 그동안 강의자료를 정리한다. (claude.ai에서는 받아쓰기를 하지 않고 전사문을 받는다.)
3. 판서 사진: 칠판 부분만 잘라 넣는다(사람이 나오지 않게). 내용은 [판서]로 글로 옮긴다.

## 4단계: 결과물 작성

각 결과물을 만들기 전에 해당 참고 파일을 읽는다.

| 작업 | 읽을 파일 |
| --- | --- |
| study note .md (자료 처리, 그래프·필기·판서, 번역, 수식, 녹음 반영, 필기 위치) | `references/note-rules.md` |
| 마인드맵(키워드 구조도·프린트용), 스터디 가이드, 모의고사 | `references/outputs.md` |
| .docx 사본 (글자 색·형광펜·수식) | `references/word.md` |
| 웹 페이지 묶음·아티팩트·내려받기 버튼·프린트 PDF | `references/web.md` |

마무리 점검 (결과물을 넘기기 전에):
- 수식: `python -I scripts/mathcheck.py *.md`로 모든 수식이 그려지는지 확인하고, Word는 `scripts/docx2pdf.py`로 PDF를 만들어 몇 쪽을 직접 본다(`scripts/render_pages.py`).
- 숫자: 모의고사·가이드의 계산은 파이썬으로 다시 계산해 맞춘다.
- 화면: 웹 페이지·프린트 PDF는 `scripts/browser.py shot|pdf`로 한 번 그려 보고 깨진 곳을 고친다.
- 환경 때문에 못 한 확인(브라우저·Word 없음)은 넘길 때 그렇다고 말한다.

## 5단계: 보고

작업 중에는 scratchpad의 보고 파일에 누적하고, 끝나면 다음을 보고한다.
- **빠짐 점검표**: "PDF 쪽 ↔ 노트 절" 대응표와 "녹음 파일·구간 ↔ 노트 절" 대응표, 그리고 빈칸 점검 결과. 사용자는 누락을 가장 걱정한다.
- 강의자료와 녹음이 다른 곳: 위치 / 강의자료 / 녹음(파일명·타임스탬프)
- 녹음으로 고친·보완한 필기: 위치 / 원래 판독 / 고친 내용 / 근거 시각
- 필기 위치를 옮긴 것: 필기(PDF 쪽) / 원래 위치 / 새 위치 / 근거 (그대로 둔 것과 이유도)
- 받아쓰기 불확실 용어, 맞는 위치가 없는 내용

녹음에서 시험 형식·범위 공지를 찾으면 노트에 넣지 않고 따로 보고하며, 모의고사 형식에 반영한다.
